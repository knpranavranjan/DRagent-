An explainable, uncertainty‑aware DR screening cascade.

Six stages from raw fundus photograph to a clinical route, where every number a decision rests on is measured on a named dataset — and every weakness is written down beside it.

This is a research prototype, not a medical device. It has no regulatory clearance and has not been validated in a clinical trial. It screens; it does not diagnose. Every result requires review by a qualified clinician. Nothing on this page should be used to make a decision about a patient.

This page describes the project. It is not the application — there is nothing here to upload an image to. The working system runs on a machine with MATLAB and is reached over a private tunnel; the last section explains why it cannot be hosted here.

Pipeline

What happens to an image

Each stage can stop the cascade. An image that fails the quality gate never reaches a model, and a triage filter that sees nothing suspicious ends the pass early — so most images cost far less than the full run.

0
Quality gate Classical features decide whether the photograph is gradeable at all. Ungradeable images return RECAPTURE rather than a guess.
1
Triage filter A small binary network asks whether anything warrants a closer look. Its threshold comes from site rules, not from the model file.
2
DR grading EfficientNet‑B0 with a CORAL ordinal head — severity is ordered, so the head predicts cumulative probabilities rather than independent classes.
2b
Maculopathy A head on the frozen grading encoder. This refers independently of DR grade, because a low grade with macular involvement still needs an ophthalmologist.
3
Lesion segmentation A U‑Net tiled at native resolution marks exudates, microaneurysms and haemorrhages. Explanation only — no routing rule reads it.
—
Calibration & uncertainty Temperature scaling on the shared logit, with an uncertainty estimate that drives abstention when the model should not be trusted.
▸
Deterministic decision engine Versioned rules — not a model — map the evidence to ROUTINE, REFERRAL, URGENT, RECAPTURE or HUMAN REVIEW. This is the only thing in the system that produces a clinical route.

Honest limits

What this system does not do

It does not diagnose. It sorts images into routes so a clinician sees the urgent ones first. The route is a triage decision, not a finding.
Its explanations are not a map of disease. Grad‑CAM reaches IoU 0.052 against expert lesion masks. It shows where the network looked, which is not where the disease is. The report labels it that way.
Performance drops off‑domain. QWK falls from 0.895 to 0.75 on an external set. Per‑site calibration is mandatory — uncalibrated, external referable sensitivity measured 0.507 against 0.904 calibrated.
The quality gate is the weak link. It rejected 19 of 71 referable images externally. Those become RECAPTURE, which is only safe in a workflow where the retake reliably happens.
The decision rules are untested on real outcomes. No public dataset pairs fundus images with symptoms, acuity and grade, so the rules are covered by 21 scenario tests rather than by clinical validation.
An absent marking means nothing. Soft‑exudate Dice is 0.095. A retina with no lesions drawn on it has not been shown to be healthy.

Orchestration

An agent that gathers evidence, and never decides

An observe‑plan‑act‑replan layer chooses which stages to run for a given case and adapts when a capture is poor or a result is ambiguous. It calls eight registered tools; capabilities it must not have are not withheld from it, they simply do not exist as tools.

The boundary is structural rather than advisory: a clinical route that did not come from the deterministic engine raises an error at construction. A parity test asserts the agent's numbers are bitwise identical to the plain cascade's, because two copies of medical logic drift, and a drifted copy would hand a clinician figures no validated pipeline ever produced.

Verified, not asserted

62 agent tests, 21 decision scenarios. The agent reorders work; it cannot change an answer.

Architecture

Why the live system is not hosted on this domain

Every stage is MATLAB code loading a .mat file. No serverless platform offers MATLAB, it cannot be installed into a function image, and the licence is bound to a machine. The job queue is a directory that two processes share, which a stateless function with an ephemeral disk cannot participate in.

So the system runs on a workstation and is reached through an outbound tunnel, gated by an access key checked on every request. This page is static documentation; the application is not deployed here and no image submitted to this domain would reach a model. 

python run.py --tunnel

Starts the session server, the MATLAB worker and the tunnel as one process group, prints a key‑gated HTTPS link, and tears all three down together on exit.
